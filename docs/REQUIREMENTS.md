# 需求與邊界：實作前的 TDD 基準

2026-10-27。使用者本輪需求區仍保留模板文字，因此本專案採用現有 Life World 最新決策 U-01～06，建立可在本機操作的 Python MVP。這次使用者已明確授權建立新 App 資料夾。

## 必須實作

1. 訪客建立伺服器 session；Bio 後建立首個目標，目標與三項行動／Lv1–3／各自星期排程保存成功後才誕生 Lumi。未建立目標，後端也拒絕世界資料、事件、人物及創作功能。
2. 訪客可保存無人物事件。人物建立或關聯需先升級；升級成功保持 owner、目標、草稿與積分，不複製資料；取消可回到原草稿。
3. 原文不被摘要覆寫；整理結果只是候選。使用者明確確認摘要、貢獻與後續任務後才產生正式經歷與積分。每項行動可確認正數小數貢獻，伺服器精確累加，AI 不裁定達標。
4. 行動累計無論多少都不自動完成目標；上傳有效佐證後，由使用者明確確認終極成果。證據須屬於同一 owner 與目標。
5. 補記保留帶時區的實際發生時間與伺服器提交時間；允許過去日期，確認後有積分且可回讀。同一提交重試不重複累加／發獎。
6. 人物可留空；無人物與有目標或無目標的事件均可保存（首次目標仍必須先完成）。
7. 本機資料以 SQLite 持久化，重啟 App 後可回讀。認證採隨機 HttpOnly session、CSRF、Argon2 密碼雜湊；本機帳號模式不宣稱完成正式受管身份驗證。
8. 人物歷史與私人準備／模擬／訊息筆記；模擬與訊息不更新真實經歷、貢獻、人物事實或積分。文字安全呈現，無自動發送。

## 正常、異常與邊界

- 無 session／過期／偽造 session、CSRF 缺失、跨來源寫入、登出後舊 cookie。
- 首次目標缺 Bio、少於／多於三行動、空白名稱、非法 Lv、星期重複或越界。
- 小數貢獻精度、0／負數／NaN／Infinity／極大值、外部 action ID、超過目標值但不自動完成。
- 無時區、未來發生日期、跨午夜與很早的補記；資料庫時間統一 UTC，UI 用使用者時區。
- 相同 request ID 相同內容回傳原回執；相同 ID 不同內容回 409；同草稿用新 ID 再確認也不能重複發獎；併發確認保持單次寫入。
- 草稿 revision 衝突、AI／整理失敗、確認中途例外完整 rollback、刷新後草稿恢復。
- 訪客人物門檻、跨 owner 的人物／目標／草稿／證據／action ID、帳號切換與既有帳號衝突。
- 空檔、超大檔、格式偽造、損毀圖片、惡意檔名、錯誤目標證據、未確認或無佐證完成。
- 完成後的經歷與貢獻更正政策未決：不提供隱含的完成後改帳功能，回明確 policy_required，不抹掉草稿。

## 明示的開發設定，非正式產品裁定

`DemoPolicy` 集中管理：每筆人工確認的真實經歷預設 1 分、允許 PNG/JPEG 佐證、上限 5 MiB、每個貢獻最多六位小數、期限與帳號限制。測試可替換設定以證明不硬編。

這些設定讓本機功能能實際操作，**不是宣告未決規則已獲核准**。GE-04 不做負向衰減；不實作主動結束／恢復／完成後改帳。相同真實事件由不同草稿再次輸入的辨識仍待正式規則；目前去重保證針對同一提交與同一草稿。

## 技術與範圍

Python + FastAPI、SQLite、純 HTML/CSS/JavaScript，無 Node 建置需求。本機手動整理保留原文，不假裝已接真實 AI；AI 以 provider 介面預留。正式受管認證、PostgreSQL、雲端物件儲存、正式計分政策、完整 Figma／小劇場／夜間關懷與部署為後續整合項目。

先寫 pytest，保留首次失敗輸出，再實作並執行整合測試。不得以 mock 成功取代真實資料庫驗證。
