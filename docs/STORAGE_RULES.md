# 檔案、素材與資料存放規則

日期：2026-10-28。適用團隊協作；現有路徑維持不動，未來位置明示為目標。本儲存庫目前公開，僅提交適合公開的程式、規格及核對過的虛構驗收素材。

## 1. 儲存庫內的位置

| 內容 | 位置 | 規則 |
|---|---|---|
| 正式 Python／現有前端 | `app/`、`app/static/` | 正式整合與交易由全端審查，不被元件工作包直接覆寫 |
| 現有遷移 | `app/migrations/` | 已發布 migration 不改寫歷史；新 PG 方案先契約／獨立測試再增量處理 |
| 測試／工具 | `tests/`、`browser_tests/`、`scripts/` | 用隔離虛構資料，寫明命令與環境；工具不得預設指向正式資料 |
| 共用規格 | `docs/` | [索引](SPEC_INDEX.md)連入；現況、目標、提案、待決、歷史分開 |
| 分工／任務／提示詞 | `docs/team/` | 一位主責、來源 commit、修改範圍、審查者與交付證據 |
| 元件展示 | `collaboration/ui-kit/`（待工作包建立） | 獨立 React／TS 展示，不接真實資料；不能當作正式 App 已移植 |
| 歐桑完整交付包 | `collaboration/ui-kit/` 內 `content/`、`evaluation/`、`assets/`、`src/`、`docs/`、`tests/` | 十五位人物／六場景、來源／評估、完整資產／元件／動效、測試與 Jerry 接入說明；一份專案完整交付 |
| 資料核對報告 | `collaboration/data-audit/`（待工作包建立） | 放模型、差異、測試設計或隔離工具，不放真實 DB dump |
| 未來正式 React | 尚未建立，於整合契約確定位置 | 不讓每人各建一個正式前端或擅自調整根目錄工具鏈 |
| 視覺／聲音候選 | 工作包內 `assets/` 子目錄 | 附來源、工具、格式、大小、透明／音量／時長、使用依據及產品審查；通過後由整合任務搬入正式資產位置 |
| 公開驗收證據 | `docs/artifacts/` 與 `docs/*_GREEN.txt` 等 | 只用已核對虛構資料；結果附日期、命令與限制，不夾真實個資／token |
| 相依設定 | 各專案設定檔與鎖定檔 | 提交鎖定檔，不提交套件安裝目錄、建置／快取或個人 IDE 設定 |

不更名／搬動原始交接包及歷史原型。App 之外的本機工作區不會隨 Git push 上傳；共用執行規格須放 App 儲存庫內。新增／更名／刪除文件，同步修正相對連結與索引。

## 2. 不進 Git 的內容

- 真實使用者資料庫、匯出、上傳圖片／音檔／名片／截圖、個人草稿及帳號內容。
- `.env`、API key、密碼、session／復原碼、服務帳號私鑰及秘密設定；只提交沒有秘密的 `.env.example`，夥伴自行設定。
- `.venv/`、`node_modules/`、建置產物、瀏覽器暫存／失敗追蹤、個人快取與私有備份。使用 `.gitignore` 配合人工核對；已追蹤檔不因加入忽略規則就自動消失。
- 本機完整交接壓縮包與備份放已忽略的 `data/backups/`；不把每份壓縮包重複堆到原始碼儲存庫。共同起點以 Git commit 為主。

本機資料預設 `data/lifeworld.sqlite3`，以 SQLite backup API 備份；不要在服務運作時只複製主檔而漏 WAL。團隊測試必須另設 `LIFEWORLD_DATA_DIR`，不可把正式資料當 fixture。

## 3. 雲端目標（尚未部署）

- PostgreSQL／Cloud SQL 保存帳號、權限、草稿／正式紀錄、來源、工作狀態與帳本；Cloud Storage 私人 bucket 保存影像／音檔等素材，DB 保存安全參照及歸屬。
- 物件名稱用系統產生的識別碼，不以姓名、電話或原始檔名當公開路徑；原檔名若需保存，放受權限保護的 metadata。
- 讀取先驗 owner；不將 bucket、上傳檔或永久公開 URL 當分享機制。下載／預覽介面與權限由全端審查。
- 原始素材、辨識文字與人工摘要分開；同一事件多附件不重算見面或積分。辨識工作失敗保留可恢復狀態，不聲稱素材已保存到尚不存在的服務。
- GCP 憑證由服務身分與 Secret Manager 管理，不把私鑰打包進 container；測試與試用環境隔離。

## 4. 尚待決定的資料政策

| 項目 | 目前規則／處理 |
|---|---|
| 素材／草稿保留多久 | 待產品與全端決定；本輪不建立自動過期刪除 |
| 移除附件如何影響已確認來源 | 需定義撤回、衍生資訊與稽核邊界；不默默刪帳本或覆寫事實 |
| 備份頻率、保留期限及可接受資料損失 | 待試用部署契約確認並實測還原 |
| 匯出、帳號刪除與備份清除 | 待產品政策與工程流程確認，不假裝現有 App 已支援 |
| AI 廠商資料保存／外送範圍 | 服務未選定；串接前審查，不因採 GCP 就指定 Gemini |
| 新素材大小、格式與大型檔案管理 | 目前成果佐證依 DemoPolicy；多模態門檻是待審提案，不直接覆蓋既有政策 |

待決項目在對應工作包標示「待決／阻擋」，由使用者確認產品政策、全端核對技術與資料夥伴驗證；不靠 GPT 補出未經確認的保存期限。
