# Life World｜共同產品基準

日期：2026-10-28。由使用者歷次確認與本次共同規格發布要求整理；詳細原則見 [PRODUCT_GUIDE](PRODUCT_GUIDE.md)。本文區分現有能力與目標，不替待決政策定案。

## 產品與核心旅程

「透過現實中的努力，打造一個屬於自己的世界。」讓努力被看見，使用者暫時離開仍受歡迎；不設寵物死亡、缺席扣分或逼迫登入的懲罰。

目標 → 可自主執行的行動與安排 → 記錄真實經歷 → AI 候選／手動整理 → 人工確認 → 後續任務、進度與虛擬回饋 → 回讀及接續。

優先驗證業務情境，但人物、經歷、目標及獎勵維持共用核心；不把未來學習／健身／生活功能強行轉成 CRM 欄位。POC 採手機網頁，保留世界／目標／紀錄／關係四主分頁。

## 不可混淆的語意

| 名詞 | 規則 |
|---|---|
| 終極成果／行動 | 行動累計不會自動完成終極成果；需佐證與使用者明確確認 |
| 排程／完成 | 排程勾選是打算做，正式貢獻另外確認；不因勾選日期發分 |
| 發生時間／建立時間 | 可補記過去經歷，按使用者時區呈現，分別保存兩種時間 |
| 原文／摘要／候選 | 原始來源不被摘要覆寫；AI 不虛構事實，候選不自行確認 |
| 參與／互動／提及 | 同場不自動算直接互動；提到某人不等於出席；配對身分不等於建立私人關係 |
| 使用者審閱／第三方證實 | 自己確認紀錄，不宣稱所有參與者都證實內容 |
| 互動事件／多筆紀錄 | 同一見面可連多筆經歷與附件；只有實體互動事件計見面，合併不重發分 |
| 人物資訊／來源 | 四維度由使用者確認的來源支持；未知顯示尚未了解，衝突不默默覆蓋 |
| 私人小劇場／正式經歷 | 準備、模擬與訊息草稿不更新正式人物、進度或積分；真實回顧回到同一確認服務 |
| 回饋／動畫 | 唯一確認回執決定入帳，動畫可跳過；夜間仍使用相同計分政策 |

## 既有使用者規則

沿用 [U-01～06](context/LATEST_PRODUCT_DECISIONS_2026-10-27.md)：首次 Bio 與目標不可繞過、目標蛋後 Lumi 出場；人物操作需升級並保持 owner；貢獻由使用者決定；成果有佐證與人工確認；補記保存與去重；人物選填。升級取消／返回不能丟草稿，跨帳號資料不可存取。

## 目前與下一階段

- **現有 v0.3.0：**Python／FastAPI、SQLite、原生前端，文字草稿與人工確認、人物三分頁／四維度／來源、互動與小劇場、交會取代星圖。AI 是手動替代，成果圖片上傳不等於多模態紀錄。
- **下一階段：**React＋TypeScript、PostgreSQL、GCP；月排程預設、週規律選用，多模態草稿及夜間共用變體。詳細狀態與待審參數見[流程規格](team/FLOWS_AND_STATES.md)。
- **夜間：**使用者啟用、同休息窗口不重複關懷、可略過、無聲、先存草稿與跨日補記；不診斷睡眠、不自動 Pause、不改正式獎勵資格。
- **首輪試用：**5–8 人。邀請與帳號復原、私有素材、部署與還原先完成；11/13 為 POC 目標，實際工期依第一包與團隊可投入時間確認。

開發用每筆經歷一分、成果 PNG／JPEG 上限 5 MiB 等仍是 DemoPolicy，不能當成正式產品裁定。語意去重、完成後更正、素材保留期限、AI 廠商及雲端細節見[待決索引](SPEC_INDEX.md)。

## 完成標準

每個功能有使用情境、輸入／輸出、例外退路及測試。Python 採 pytest TDD；前端另驗手機／桌面流程、返回與畫面；PG／AI／實機以真實環境驗證，未執行必須明說。程式可審查、資料可回讀、失敗保得住草稿，才記錄為對應階段完成。
