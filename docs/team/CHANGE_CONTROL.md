# 成員、任務與產品變更的同步規則

日期：2026-10-28。來源：使用者要求將相關規則寫入本機開發指引，待正式規則確定、公告同仁後再推送 GitHub。

**狀態：待定案／公告的共用草案。** 2026-10-28 Boyi 最新指示「先把git推上去」，本次依此授權先發布草案供團隊閱讀；不表示規則已正式生效或已公告。本文沒有自動同步、公告、授權 GitHub 成員或部署的功能。

## 1. 適用範圍與本機執行原則

適用於成員／職責、任務歸屬、產品方向／行為、技術契約及共用檔案／資料規則的變更。收到變更時，先核對現況、影響與既有工作，再更新本機相關文件；已核准範圍內的一般修正依原開發、測試與 PR 流程處理。

- 本機資料、Git commit、GitHub、夥伴工作目錄及雲端部署分別記錄狀態；文件改動不等於功能實作或資料遷移完成。
- GitHub 以提交／推送更新，夥伴以取得對應 commit 並安全整合更新本機；已開工分支先確認未提交內容與衝突，不直接覆蓋。
- 成員名單變更另核對儲存庫、GCP、資料庫、素材與秘密的存取權；文件不會自動改權限，未實作就標待處理。
- 公告由使用者或其指定人處理。未收到明確代發指示，不透過工具傳訊給同仁；發布文件不當成已完成公告。

## 2. 必須同步核對的內容

| 變更 | 本機先核對／更新 | 另外處理與驗證 |
|---|---|---|
| 成員加入、退出、職責調整 | 共同指引當期人力、分工、任務主責與審查者、交接與提示詞 | 存取權、待交接成果與未完成任務；不公布私人帳號資料 |
| 任務新增、取消、轉交、優先級改變 | 任務看板、依賴／阻礙、工作包範圍、驗收與交付模板內容 | 接手版本、在途分支、未提交工作及受影響契約 |
| 產品方向、機制、流程或規則改變 | 決策狀態、產品基準、流程／畫面、共同規格索引、後續工作 | 需要實作的 API、程式、資料模型、測試與遷移另列任務，不預填完成 |
| 框架、部署、資料或素材存放改變 | 架構、API、存放規則、設定範例、工作指引與風險 | 相容、權限、資料核對、備份／還原、部署及回復依實際影響驗證 |
| 已核准變更完成 | 演進與驗收、已實作狀態、共同版本與已知限制 | 依變更執行測試；純文件做內容／連結／差異檢查，歷史結果不冒充本輪 |

只更新受影響項目，保留原始交接包與歷史證據。發現規則衝突須列出來源、差異及決定者，不以改測試或改文案偷偷降低要求。

## 3. 規則定案、公告與 GitHub 發布

狀態順序：**本機草案 → 待審查 → 已定案待公告 → 已公告待發布 → 已發布 → 成員同步確認**。部署另記，不在這條狀態內自動發生。

1. **本機準備：**記錄變更前後、原因、影響、待決、責任人與文件修訂；完成必要檢查，整理同仁可閱讀的變更摘要。
2. **定案：**使用者確認產品／組織規則；涉及 API、資料與部署由全端審查，資料夥伴核對相關資料。記錄版本／日期與決定，不把建議升為正式規則。
3. **公告：**使用者或指定人向受影響同仁公告已定案版本、變更摘要、生效方式及需做的事；記錄公告人、日期、管道與版本，必要時保留可查證的紀錄，不保存私密對話全文。
4. **發布前核對：**已定案與公告版本須對應本次待推內容，既有發布範圍授權須足以涵蓋變更。條件齊全即可依授權繼續，不重複索取相同許可；資訊不明才詢問缺少的事實。
5. **正式推送：**依團隊分支／PR 流程提交、推送與整合，讀回遠端核對，記錄完整 commit。定案或公告紀錄未完成時，本批規則保持本機待發，不推送含該規則的分支或 PR。
6. **同仁同步：**提供正式 commit 與更新摘要，記錄需更新的工作包。各成員取得、整合並回報相應版本；無法操作同仁電腦時不能宣稱已全部同步。

公告後若內容有實質改變，先更新版本並重新確認受影響同仁收到的內容，再正式發布。另有使用者明確授權草案對外審閱時，依該次範圍處理並標草案，不冒充已定案公告。

先前共同基準 `d82171abe44e2ca0f882a82a20a6df720265ce47` 是已授權且完成的歷史發布；本規則不改寫其紀錄，也不把先前發布授權自動延伸到本批待定規則。
