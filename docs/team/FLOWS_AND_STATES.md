## 1. 登入、首次引導與返回

| 情境 | 行為與退路 | 狀態／驗收 |
|---|---|---|
| 首次試用 | 邀請進入 → 訪客或登入 → Bio → 首個目標／三行動／排程 → 核對建立 → Lumi 誕生 | 邀請為待實作；Bio／首目標不可繞過；孵化前不讓 Lumi 第一人稱說話 |
| 已有帳號 | 登入 → 原世界；與現有訪客資料衝突時明確選擇 | 帳號切換不偷偷合併或複製世界 |
| 人物操作 | 訪客升級 → 返回原草稿／人物／目標上下文 | 升級成功保留 owner；取消、失敗保留草稿；不要先清空再要求登入 |
| 過期／錯誤 | 顯示登入錯誤或過期原因，提供恢復操作 | 不把草稿顯示成已保存；不在畫面或日誌回顯密碼 |
| 復原 | 輸入一次性復原碼 → 設新密碼 → 舊 session 撤銷 | 待實作；碼只保存雜湊，換密碼不改 owner／帳本；碼與密碼均遺失的政策需明示 |

## 2. 單一目標與三個習慣（v0.4 已實作）

2026-10-29 已確認並實作增量：名稱僅更正、單位與用途固定；今天／未來日期可調，新用量依目標固定時區隔天生效。用量版本與回顧快照保留歷史，不重算已存投入／積分；取消不寫入，失敗保留，版本／午夜衝突重新核對。見[最新驗收](../HABIT_WIREFRAME_ACCEPTANCE.md)。

操作：目標命名 → 達成的樣子與必選截止日 → 三個重要習慣逐一確認 → 檢查總覽 → 開始挑戰。每次預期量預設 1 次，可展開修改；舊 Lv 與總量原樣保留。

- 初期一個帳號只保留一個未結束目標；待回顧與待補設定仍占名額。多目標封測後再評估。
- 月是預設編輯週期，週可選，不是目標預設期限。月／週呈現同一日期資料；星期快選套用整個目標期間，單日可調整，畫面明示操作範圍。這取代前輪「當期／檢視後複製下一期」候選方案。
- 勾選是安排要做，不計完成或獎勵；每個習慣至少一天。日期只在目標期間內，修改安排保留過去與真實累計。
- 截止日包含目標固定時區整天，翌日待回顧。人工選擇成果完成、延長或結束；完成與提前結束不懲罰。歷史分已完成／曾經挑戰，後者區分到期未完成／提前結束。
- 待回顧仍能保存經歷；貢獻先待處理，延長後逐筆核對，不自動補算；封測不計獎勵。歷史不提供恢復／重試捷徑。
- 舊目標不猜期限；舊多目標需逐一人工完成或結束，再補保留者設定。建立草稿按 owner 保存在目前裝置，返回、取消與刷新可接續，不承諾跨裝置同步。

詳細契約見 [API](../API.md)，本輪測試、截圖與限制見[單一目標驗收](../GOAL_FLOW_ACCEPTANCE.md)。本機素材／錄音控制與校對已於 2026-10-29 接入，見[元件契約](MEDIA_COMPONENT_CONTRACT.md)及[驗收](../MEDIA_COMPONENTS_ACCEPTANCE.md)。外部辨識、雲端素材與夜間服務仍待整合，以下未完成部分不當成交付。

## 3. 一般紀錄共用流程

EX01 輸入素材與發生時間 → 保存草稿 → EX02 AI 候選／手動整理 → 人工校對 → 確認交易 → EX03 回饋 → EX04 紀錄列表。

- 入口：文字、錄音／音檔、圖片／截圖、拍照及名片。可混合於同一經歷；目標／人物上下文可帶入，人物選填。
- 原始素材、辨識文字與可編輯摘要分開；來源必須可回看。純影像／音訊可先存本機素材草稿並從紀錄頁接續，不強迫填假文字；伺服器經歷草稿仍需人工整理文字。
- 參與、直接互動、提及、身分配對、人物資訊、行動貢獻與後續任務各自確認；候選不自動寫正式資料。
- 名片可進入獨立人物草稿；先校對與配對／新增，不為保存名片捏造一次經歷、見面或獎勵。
- 附件顯示選取／預覽／上傳中／成功／失敗／重試／移除。成功必須有伺服器回執，不能只看進度動畫。
- 多附件不是多次見面；AI 失敗保留原素材及其他輸入，可手動整理或先存草稿。
- 確認中避免連點；逾時使用同一提交識別核對狀態，依正式回執顯示進度與回饋。跳過動畫不影響已入帳成果。
- 返回保留日期、文字、附件、摘要、選擇與來源上下文；對尚未上傳素材與已存伺服器草稿清楚區分，刷新前提醒未保存，不承諾不存在的離線同步。

**待審限制：**前輪建議每筆五附件、圖片 10 MiB、音訊五分鐘且 20 MiB，為候選門檻，需 LW-TECH-001 核對格式、裝置及服務限制再定；不改既有成果佐證的 5 MiB 政策。AI 供應商、端點與素材保留／刪除政策尚待確認。

## 4. 錄音狀態與回呼邊界

| 狀態 | 可見資訊／操作 | 成功去處 | 失敗與取消 |
|---|---|---|---|
| idle | 錄音目的與開始按鈕 | requesting_permission | 仍可文字或上傳音檔 |
| requesting_permission | 等待系統麥克風授權，不假裝已錄音 | recording | 拒絕／無裝置／不安全環境顯示原因與替代入口 |
| recording | 真實錄音時長、停止、取消；音量圖只能來自真實訊號或明示模擬 | ready | 中斷停止使用麥克風，保留可用內容並說明限制 |
| ready | 明確「上傳並轉文字」、選擇性試聽、移除／重新錄製；非即時轉錄，不自動播放或上傳 | uploading | 重錄／移除先處理舊資源，其他文字不清空 |
| uploading | 進度或不定進度、取消；不顯示辨識完成 | recognizing | 保留本機素材並重試；取消未必能撤銷已到伺服器的工作，需查狀態 |
| recognizing | 工作狀態，可離開至草稿，不承諾精準百分比 | review | 失敗可重試／手動，原素材仍在 |
| review | 轉錄與摘要可校對，來源可回看 | EX02 人工確認 | 編輯不覆寫原始素材、不自動套用人物與貢獻 |
| error | 可理解原因、重試／回上一步／文字或音檔替代 | 對應狀態 | 不丟其他輸入，不把取消顯示為完成 |

UI 元件接受狀態、時長、進度（可無）、錯誤及操作回呼，由容器處理麥克風／上傳／API。本機 App 控制器已接入，辨識成功案例使用明示測試替身；預設未設定外部提供者。歐桑 React 候選仍需獨立交付與審查，不因本機接入就宣稱整包完成。

## 5. 夜間關懷與 Quiet 共用變體

- 2026-10-29 Boyi 已確認：首次於帳號當地 23:00–07:00 使用時輕量詢問，同意後按時段自動切換，可關閉／修改時段；手動 Quiet 可選。不推測睡眠，不再採舊候選「起床前八小時」作預設。跨日與夏令時間按帳號時區處理；目前僅[完整原型](../../collaboration/flow-wireframe/README.md)示範，正式服務待實作。
- 使用者啟用後，同一休息窗口最多一次完整關懷。略過、記錄一下、準備休息皆可；準備休息不暫停目標、不扣分、不阻斷功能。
- GE05 關懷 → NR01 安靜輸入 → NR02 整理 → NR03 人工確認 → NR04 靜態回饋 → NR05 安靜世界。
- NR06 AI 失敗接手動／保存；NR07 待整理草稿；NR08 跨日補記；NR09 設定。NR05 仍可開始另一段紀錄或查看草稿。
- 凌晨補記提供昨天／今天／自訂，事件發生時間與建立時間分開。自動關懷仍遵守首次目標與 Lumi 出場順序。
- 一般／夜間使用同一草稿、確認與保存回執；夜間無聲、弱化動畫、柔和對比但仍可讀，不藉安靜模式改動投入資格；封測不計獎勵。
