## 1. 登入、首次引導與返回

| 情境 | 行為與退路 | 狀態／驗收 |
|---|---|---|
| 首次試用 | 邀請進入 → 訪客或登入 → Bio → 首個目標／三行動／排程 → 核對建立 → Lumi 誕生 | 邀請為待實作；Bio／首目標不可繞過；孵化前不讓 Lumi 第一人稱說話 |
| 已有帳號 | 登入 → 原世界；與現有訪客資料衝突時明確選擇 | 帳號切換不偷偷合併或複製世界 |
| 人物操作 | 訪客升級 → 返回原草稿／人物／目標上下文 | 升級成功保留 owner；取消、失敗保留草稿；不要先清空再要求登入 |
| 過期／錯誤 | 顯示登入錯誤或過期原因，提供恢復操作 | 不把草稿顯示成已保存；不在畫面或日誌回顯密碼 |
| 復原 | 輸入一次性復原碼 → 設新密碼 → 舊 session 撤銷 | 待實作；碼只保存雜湊，換密碼不改 owner／帳本；碼與密碼均遺失的政策需明示 |

## 2. 目標與行動排程

操作：目標成果 → 三項行動與各自單位／Lv → 各自排程 → 核對 → 保存。每個行動的選擇互相獨立。

- 預設為起始日起一個月，例如 10/27–11/26；週規律可選。正式畫面按實際日期與使用者時區排列，並非永遠四列或 28 格。
- 點星期標頭批次安排當期相同星期，再逐日調整；提供週一至週五、週二四六、每天、清除，及安排天數／每週分布。
- 勾選是「安排要做」。已確認貢獻與完成顯示另層，不把排程勾選寫入積分或完成狀態。
- 新目標使用新編輯器；舊目標保留原週規律，可由使用者選擇轉換。修改未來規則要有生效日／版本，保留歷史與已確認成果。
- 日期按本地日期處理，不把 UTC 午夜當使用者當天。未保存離開、保存失敗、版本衝突均須有保留／重試／重新核對退路。

**待審細節：**預設採「檢視後複製下一期」；月底採下一月同日作排他終點、無同日取月底並保存原錨點以免漂移。以上是前輪規劃的預設方案，需在實作前由產品／全端確認，不能被元件展示默默定案。既有三項行動與 Lv1–3 不因新排程自行刪除。

## 3. 一般紀錄共用流程

EX01 輸入素材與發生時間 → 保存草稿 → EX02 AI 候選／手動整理 → 人工校對 → 確認交易 → EX03 回饋 → EX04 紀錄列表。

- 入口：文字、錄音／音檔、圖片／截圖、拍照及名片。可混合於同一經歷；目標／人物上下文可帶入，人物選填。
- 原始素材、辨識文字與可編輯摘要分開；來源必須可回看。單純影像／音訊草稿不強迫填假文字，待 API 擴充後才可正式使用。
- 參與、直接互動、提及、身分配對、人物資訊、行動貢獻與後續任務各自確認；候選不自動寫正式資料。
- 名片可進入獨立人物草稿；先校對與配對／新增，不為保存名片捏造一次經歷、見面或獎勵。
- 附件顯示選取／預覽／上傳中／成功／失敗／重試／移除。成功必須有伺服器回執，不能只看進度動畫。
- 多附件不是多次見面；AI 失敗保留原素材及其他輸入，可手動整理或先存草稿。
- 確認中避免連點；逾時使用同一提交識別核對狀態，依正式回執顯示進度與回饋。跳過動畫不影響已入帳成果。
- 返回保留日期、文字、附件、摘要、選擇與來源上下文；對尚未上傳素材與已存伺服器草稿清楚區分，刷新前提醒未保存，不承諾不存在的離線同步。

**待審限制：**前輪建議每筆五附件、圖片 10 MiB、音訊五分鐘且 20 MiB，為候選門檻，需 LW-TECH-001 核對格式、裝置及服務限制再定；不改既有成果佐證的 5 MiB 政策。AI 供應商、端點與素材保留／刪除政策尚待確認。

## 4. 錄音狀態與回呼邊界

| 狀態 | 可見資訊／操作 | 成功去處 | 失敗與取消 |
|---|---|---|---|
| idle | 錄音目的與開始按鈕 | requesting_permission | 仍可文字或上傳音檔 |
| requesting_permission | 等待系統麥克風授權，不假裝已錄音 | recording | 拒絕／無裝置／不安全環境顯示原因與替代入口 |
| recording | 真實錄音時長、停止、取消；音量圖只能來自真實訊號或明示模擬 | preview | 中斷停止使用麥克風，保留可用內容並說明限制 |
| preview | 試聽、重錄、移除、提交；不自動播放或上傳 | uploading | 重錄／移除先處理舊資源，其他文字不清空 |
| uploading | 進度或不定進度、取消；不顯示辨識完成 | recognizing | 保留本機素材並重試；取消未必能撤銷已到伺服器的工作，需查狀態 |
| recognizing | 工作狀態，可離開至草稿，不承諾精準百分比 | review | 失敗可重試／手動，原素材仍在 |
| review | 轉錄與摘要可校對，來源可回看 | EX02 人工確認 | 編輯不覆寫原始素材、不自動套用人物與貢獻 |
| error | 可理解原因、重試／回上一步／文字或音檔替代 | 對應狀態 | 不丟其他輸入，不把取消顯示為完成 |

UI 元件只接受狀態、時長、進度（可無）、錯誤及操作回呼，由容器處理麥克風／上傳／API。歐桑本輪的錄音元件提供完整可操作狀態展示，其他資產仍按整包清單交齊；真實錄音與 API 整合屬 LW-CORE-001，不混淆驗收。

## 5. 夜間關懷與 Quiet 共用變體

- 提供關懷開關、起床時間、IANA 時區與安靜偏好；自動關懷預設關閉，手動 Quiet 可選。休息區間按起床前八小時計算，處理跨日與日光節約時間。
- 使用者啟用後，同一休息窗口最多一次完整關懷。略過、記錄一下、準備休息皆可；準備休息不暫停目標、不扣分、不阻斷功能。
- GE05 關懷 → NR01 安靜輸入 → NR02 整理 → NR03 人工確認 → NR04 靜態回饋 → NR05 安靜世界。
- NR06 AI 失敗接手動／保存；NR07 待整理草稿；NR08 跨日補記；NR09 設定。NR05 仍可開始另一段紀錄或查看草稿。
- 凌晨補記提供昨天／今天／自訂，事件發生時間與建立時間分開。自動關懷仍遵守首次目標與 Lumi 出場順序。
- 一般／夜間使用同一草稿、確認與獎勵回執；夜間無聲、弱化動畫、柔和對比但仍可讀，不改正式計分資格。

## 6. 第一輪共用元件與驗收

Button、TextField／TextArea、Card、StatusMessage、Dialog／BottomSheet、AttachmentCard、RecorderPanel、ScheduleGrid。從[現有色彩變數](../../app/static/tokens.css)及[原圖對照](../PEOPLE_RESTORATION.md)取材；色票是現況來源，不宣告為永遠不變的正式品牌規範。

- 每個可操作元件有鍵盤／可見焦點、可讀標籤，錯誤不只靠顏色；觸控目標以 44 CSS px 為設計目標。
- 對話框／底部面板處理焦點進出、關閉與返回；有未保存內容時先提供退路。減少動效、長文字與手機鍵盤不遮住必要操作。
- 390×844 與桌面逐頁檢查；窄螢幕排程不溢出，錄音狀態切換保留其他欄位。模擬展示與真實權限／錄音測試分開記錄。
- 任一 API 尚未審查時，展示可用明示虛構 fixture；不能以 UI 的成功狀態宣稱正式保存、辨識或發分。
