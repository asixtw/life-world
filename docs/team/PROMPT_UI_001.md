## 工具與輸入

- ChatGPT：協助閱讀、比較規格、列狀態與案例；只有聊天工具時先完成這些成果。
- Codex／IDE 與本機瀏覽器：製作、執行及驗證展示；登入自己的帳號，不共用訂閱憑證。
- 產品輸入：[共同指引](../PRODUCT_GUIDE.md)、[流程／狀態](FLOWS_AND_STATES.md)、[原圖對照](../PEOPLE_RESTORATION.md)。參考外部原型不必成為啟動前提。
- 視覺來源：[tokens.css](../../app/static/tokens.css)及[現有樣式](../../app/static/styles.css)。使用現有暖白／薄荷方向，新增值先標候選。

以下整段可複製給夥伴自己的 ChatGPT／Codex；以共同 Git commit 提供本儲存庫，舊來源包只是備援，不假設另一個聊天能讀取本機或目前對話。

```text
你正在協助 Life World 的 LW-UI-001，共用元件與錄音介面展示。
回覆與註解用繁體中文。產品主責是使用者，技術審查者是全端。

一、先確認你收到的東西
1. 閱讀 docs/team/BASELINE.md、docs/team/FLOWS_AND_STATES.md、
   docs/PRODUCT_GUIDE.md 及適用的 AGENTS.md。
2. 先對照團隊提供的 Git commit 與 BASELINE_MANIFEST.tsv；只有舊來源包時
   另記整包 SHA。若拿到舊版或檔案缺漏，先說明，不猜測其他對話內容。
3. 回報實際可用工具、作業系統、Node／套件管理器、瀏覽器及
   能否操作程式檔與執行指令。沒有本機工具時交規格，不宣稱實作。

二、目標與範圍
目前正式 App 是 Python FastAPI＋SQLite＋原生前端 v0.3.0。
目標為 React＋TypeScript、保留 Python、遷移 PostgreSQL、部署 GCP。
你只做獨立 UI 展示，不遷移正式 App，不接外部辨識服務，AI 廠商未定。

使用獨立 work/lw-ui-001 分支；只有來源包時，先在新目錄建立自己的
本機 Git 工作分支並記錄快照 SHA，不覆寫別人的修改。
展示程式只放 collaboration/ui-kit/，該目錄目前尚未建立。
可以在其中建立 Vite＋React＋TypeScript 專案、鎖定檔、展示說明與測試。
先使用原生元素與現有樣式規則；不新增整套 UI 套件或改根目錄工具鏈。
不要修改 app/、正式 API、資料庫 migration、確認交易或積分規則。

三、交付順序
1. 先列使用者情境、元件清單、狀態、資料輸入／輸出、邊界與規格衝突。
2. 先做 Button、TextField／TextArea、Card、StatusMessage、
   Dialog／BottomSheet、AttachmentCard；每個提供必要參數與操作回呼。
3. 再做 RecorderPanel，顯示 idle、requesting_permission、recording、
   preview、uploading、recognizing、review、error 狀態。
4. 讓展示者可切換權限拒絕、無麥克風、中斷、上傳失敗、辨識失敗、
   取消、重試及文字替代；狀態切換不能清空其他已輸入內容。
5. 第一包的麥克風、上傳、辨識均為明示模擬，不呼叫真實硬體／API。
   不偽裝錄音、實際音量、上傳完成或已保存。若未來要做真實錄音，另提任務。
6. 補元件 API 與使用範例，明確區分 props 狀態與容器副作用。

四、互動要求
- 每個元件有正常、停用、載入、錯誤與可讀提示；不適用者寫原因。
- 觸控目標以 44 CSS px 為目標，支援鍵盤與可見焦點、可讀標籤。
- Dialog／BottomSheet 處理焦點進出、Escape、關閉、返回與未保存內容。
- 不自動播放音訊；夜間無聲、弱化動畫但保持可讀，支援減少動效。
- 不用圖片代替按鈕、文字或其他需要操作的元件，不自行換 Lumi 外觀。
- 來源、摘要與候選分開顯示；展示不自行確認人物、進度、任務或獎勵。

五、驗證與交接
- 先列正常、錯誤、邊界及返回案例；以適當的元件／瀏覽器測試驗證。
- 驗證 390×844 與桌面、長文字、鍵盤操作、面板焦點及重試不丟輸入。
- Python 工具若有新增，依團隊 pytest 紅燈→實作→綠燈；UI 驗收不能用
  Python 測試通過代替。不要為這個展示額外造沒有用途的 Python 程式。
- 新增／修改自有程式與測試逐行有意義的繁體中文註解；模板／無註解
  格式用相鄰合法說明，空白行與自動產生檔不硬塞註解。
- 回報實際執行命令、通過／失敗／跳過數、截圖及未驗證事項。
  無法執行、依賴未安裝、只寫程式都不能宣稱已通過。
- 使用 docs/team/HANDOFF_TEMPLATE.md 交付：來源、分支／提交、變更檔、
  啟動方法、相依套件、元件參數、證據、限制與需要審查的差異。
- 展示完成不代表 App 已整合；不要推送主分支、部署或修改正式資料。
```
