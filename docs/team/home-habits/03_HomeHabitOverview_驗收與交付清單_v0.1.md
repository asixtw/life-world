## 3. QA 證據要求

- 測試環境、HEAD commit、主瀏覽器及版本、手機裝置型號、測試資料是否虛構。
- 單元測試命令／結果與最小失敗重現；重要 API 的回應結構對照（需去識別化）。
- 桌面 1440×900 與手機 390×844 完整操作截圖；另以 320px 長字、Quiet、Reduced Motion 驗收。
- 每案記錄 `pass/fail/blocked/not-run`、實際結果、關聯 issue／commit，**未執行不得勾通過**。
- 不得向 GitHub 提交真實使用者的目標名稱、經歷、錄音或帳號資訊。

## 4. 與已存在資料規則的核對

| 項目 | 本輪要求 |
|---|---|
| 目標數 | 僅一個未結束，三項習慣；若舊資料多目標以既有處理規則呈現，不自動改寫資料 |
| 日期 | 目標 `schedule_timezone`、含今天之下一日期；既有實際安排與後端日期為準 |
| 精度 | 後端 Decimal 與 `target` 為權威，不把前端 `Number` round-off 當作正式紀錄 |
| 真實經歷 | 人工確認才更新 progress，不因勾任務、點行動或劇場自動採計 |
| 互動 | 返回、重新整理、登入切換不能把本地未確認資訊誤寫正式 API |
| 獎勵 | 封測不呈現積分／養分，已有帳本不能因展示改版被重算／刪除 |
| UI 資產 | 先沿用現有 `collaboration/ui-kit`、Lumi、目標蛋與房間，新增物件需標註來源與版本 |
