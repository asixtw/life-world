# Life World｜三人協作入口

更新：2026-10-28（Asia/Taipei）。來源：使用者本次要求實施的「三人團隊分工方案」及前續暫定技術方向。文件已建立；下列工程任務尚未由此文件自動完成或派送。

## 先從這裡開始

| 讀者 | 先讀 | 第一份工作 |
|---|---|---|
| 產品負責人（使用者） | [分工](RESPONSIBILITIES.md)、[流程／狀態](FLOWS_AND_STATES.md) | 確認畫面行為、優先順序與待決項，不需自行承擔工程整合 |
| 全端夥伴 | [現況基準](BASELINE.md)、[技術審查指令](PROMPT_TECH_001.md) | 核對契約、部署與遷移風險；回報實際可投入時間 |
| 資料庫／AI 製作夥伴 | [元件任務指令](PROMPT_UI_001.md)、[資料核對指令](PROMPT_DB_001.md) | 先做 LW-UI-001，再進入資料核對；不並行承諾所有素材 |
| 所有人 | [任務看板](TASK_BOARD.md)、[交付模板](HANDOFF_TEMPLATE.md) | 使用同一份來源版本，以證據交接 |

目前 App 是 **v0.3.0／Python FastAPI＋SQLite＋原生前端**。**React＋TypeScript、PostgreSQL、GCP** 是可由使用者後續調整的目標基準，尚未遷移；AI 供應商未定。舊交接包及原型仍保留原貌。

## 交接與工作方式

1. 先核對[版本與指紋](BASELINE.md)，從產品／全端提供的共同 Git commit 開工；本機舊快照僅作先前版本保存。
2. 讀[共同規格入口](../SPEC_INDEX.md)、[存放規則](../STORAGE_RULES.md)、[協作規則](../../CONTRIBUTING.md)、[共同產品指引](../PRODUCT_GUIDE.md)及[App 工作規則](../../AGENTS.md)。本目錄補充分工，不把目標寫成現有能力。
3. 從看板領取一個工作包，填姓名、可投入時間、分支與來源快照；表內角色不是已聯絡或已承諾的實際人員。
4. 獨立分支與明確修改範圍；元件先在展示目錄完成，不改正式交易。共用 API／資料表更動先列契約差異，再由全端審查。
5. 以交付模板提交檔案、指令、結果、截圖與限制；產品確認體驗，全端確認整合，資料夥伴核對資料。
6. 工程功能完成後才移入[演進紀錄](../EVOLUTION.md)。文件、模擬、真實串接及已驗收分開標示。

## 第一輪節奏

- 使用者與 Codex：流程、狀態及驗收條件已整理在本包，接續產品確認與必要修訂。
- 全端：LW-TECH-001 契約與環境審查；可與獨立元件展示同步。
- 資料庫夥伴：LW-UI-001 共用元件與錄音展示；完成第一包後進入 LW-DB-001 只讀資料核對。
- 審查後整合一條「登入 → 目標與排程 → 紀錄 → 草稿 → 確認 → 回饋 → 再登入回讀」；再擴充其他頁面。
- 不承諾人日／固定交付日期；第一包回報環境、可投入時間與實際阻礙後再排批次。11/13 是 POC 目標，不代表這一包已承諾全部上線。

Pro／ChatGPT 用於分析與製作，Codex／IDE 用於檔案與測試；實際功能及額度以夥伴帳號為準。訂閱存取與 API 使用分開，不替 App 選定 AI 供應商，見 [OpenAI 官方說明](https://learn.chatgpt.com/docs/auth)。

此協作包最初僅在本機建立；使用者已另行授權將現有 App 與共同規格發布 GitHub，範圍與實際檢查見[發布紀錄](../GITHUB_PUBLISH.md)。React／PostgreSQL 遷移、元件製作與雲端部署仍未執行；沒有代傳訊息或邀請夥伴。
