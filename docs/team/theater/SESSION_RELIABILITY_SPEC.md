## 3. 使用情境與不變條件

1. 使用者在 A 演練中修改 B 草稿，A 的人物、來源、額度及事件不變。
2. 使用者看完歷史 H、返回並刷新，仍能接續 A；刪 H 不影響 A。
3. 建立 B 前若 A 未結束，禁止直接覆蓋；顯示可理解的選擇。
4. 一個帳號／原型資料域最多一個進行中場次（建議預設），可另存一份建立草稿、多筆已結束歷史；不承諾多場同時運行。
5. 只有已展示事件進入回顧。暫停、介入、離頁與結束使待展示內容作廢；作廢內容不因晚到回應復活。
6. 模擬、Lumi 私訊與回顧不更新人物正式事實、真實經歷、目標進度或帳本。來源只代表使用者已確認的記錄，不代表真人共同證實。
7. 保存失敗不能顯示成功或先刪舊場；需保留畫面與輸入，提供重試。

## 4. 畫面與操作契約

### 4.1 入口、建場與返回

| 情況／操作 | 畫面及結果 |
|---|---|
| 無草稿，建立我的情境 | 從情境第一步開始，清空本次暫態錯誤與錄音狀態 |
| 已有草稿，按建立 | 顯示「繼續上次草稿／另建新情境／取消」；另建須明示取代草稿，取消不改資料（建議預設） |
| 從人物卡建立 | 帶入該人物候選；有草稿時先確認，不修改 A 的參與者 |
| 上一步／返回 Hub | 保存 B 的輸入，不開始、不結束 A；提供明確的「接續目前演練」入口 |
| 確認開始，但 A 未結束 | 顯示「繼續原場／結束原場並開始新場／取消」；取消留在 B 預覽 |
| 結束 A 並開始 B | 先保存 A 已展示內容與結束原因；B 全部驗證成功且保存成功才切換，失敗不得遺失 A／B |
| 查看 H | 設定歷史檢視 ID，唯讀顯示 H；A 的輸入、狀態與身分不變 |
| 刪除 H | 確認後只刪 H；正在看 H 時回歷史列表，A 不變 |
| 再練一次 | 複製情境／目的成新草稿；重新確認人物、有效來源及假設，不沿用虛構共識、承諾、事件或額度 |

重複點開始只建立一場。離開活動畫面停止待展示計時器，回來不自動補播；保留已展示內容及未送出的文字。手機維持輸入區可達，訊息區捲動不把使用者反覆送回頁首；歷史頁須清楚標示「歷史回顧」。

### 4.2 人物／來源失效

- 建場時逐一驗證選定人物仍存在且類型相容；任何 ID 無效均阻擋開始，列出缺失項並返回人物步驟，不靜默忽略。
- 自訂場只可用已建立人物；示範角色獨立，禁止混場。不增加臨時人物入口。
- 開場後人物一般編輯不改寫場次快照。人物遭刪除、來源撤回或失效：標記失效，保留提示；禁止將失效內容加入下一輪上下文。
- 建議預設：活動場受影響即暫停，提供「結束並保存已展示內容／返回查看資料」；移除人物後須重建新場，不能原地換人。
- 歷史不得因來源消失捏造替代資料。歷史／快照的永久刪除、遮蔽與留存政策尚未定案；正式服務接入前由 Boyi／Jerry 決定，本文不授權永久保留撤回資料。快照失效標記本身不能當成已完成隱私刪除。

## 5. 模組與資料契約（本輪候選，不是正式 Schema）

| 模組 | 唯一責任 |
|---|---|
| Builder | 編輯草稿、驗證、建立快照；不更動既有場次 |
| Session Store | 管理進行中場次、持久化、revision 與遷移 |
| Director | 同一場只允許一個生成節點，控制展示／作廢 |
| History Viewer | 按 ID 唯讀查看、明確刪除；不借用 activeSession |
| Usage／Action | 玩家行動與嘗試分開計數，重送去重 |
| Host Bridge | 原型重設、示例、人物／來源失效通知及正式資料隔離 |

最低必要結構，可依現有命名調整，但必須提供欄位映射：

```text
TheaterState { schemaVersion, revision, builderDraft,
               activeSession: Session|null, history: Session[],
               viewingHistoryId: string|null }
BuilderDraft { id, revision, stage, situation, purpose,
               personIds[], selectedSourceRefs[], assumptions[], updatedAt }
Session { id, revision, lifecycle, pauseReason?, createdAt, endedAt?, endReason?,
          scenarioSnapshot, participantSnapshots[], sourceSnapshots[],
          assumptionsSnapshot[], limitsSnapshot, actions[], events[],
          generationEpoch, inputDraft, recipientIds[], lumiPrivate }
ParticipantSnapshot { personId, personVersion?, snapshotVersion,
                      name, roles[], kind, capturedAt, availability }
SourceSnapshot { sourceId, personId, sourceVersion?, capturedAt,
                 content, sourceKind, selectedByUser, validity }
Action { actionId, sessionId, text, recipientIds[], status,
         counted, attempts[], createdAt }
Attempt { attemptId, actionId, status, epoch, errorKind? }
Event { eventId, sessionId, actionId, speakerId, recipientIds[],
        behavior?, text, visibility, displayedAt? }
```

- `lifecycle`：`ACTIVE／PAUSED／ENDED`；建立草稿不算活動場。結束原因獨立保存，例如使用者結束、新場取代、額度用盡、資料失效。
- `visibility`：`queued／displayed／discarded`；只允許 queued 到 displayed 或 discarded，禁止 discarded 復活。
- `sourceKind` 分開已確認觀測、使用者轉述、情境假設、simulation；不得混寫為客觀事實。未選來源不能注入。
- 人物若無正式版本欄位，用明確的本機 `snapshotVersion` 與擷取時間；不得捏造後端 revision。來源目前只有單段文字時保存實際可用內容與其型別，明列缺少正式 source ID 的限制。
- `limitsSnapshot` 固定建場時的原型配置：1v1 八次／多人六次玩家行動、每段最多三則角色回應、Lumi 兩次、技術重試一次。現有實作每段可維持兩則；數值不是正式收費方案。
- Lumi 私訊與建議獨立保存，不出現在角色 events、角色生成上下文或公開回顧；回顧頁如提供私人筆記，須獨立區塊明示。

建議本機命令：`createDraft`、`startSession`、`submitAction`、`retryAction`、`displayEvent`、`pauseSession`、`endSession`、`viewHistory`、`deleteHistory`、`resetPrototype`。每個命令回傳成功結果或可辨識錯誤，不直接依賴 DOM 作為真實狀態來源。這不是新增 HTTP API 的授權。

## 6. 重試、額度與晚到結果

本輪計數建議預設如下，PR 必須固定測試，不可保留模糊語意：

1. 送出時建立 actionId、固定文字與對象；雙擊或同 ID 重送不新增行動。生成中禁止併行送出，但可保留下一段輸入草稿。
2. 玩家行動在本機接受時計數一次，服務錯誤不重新計數；技術重試沿用原 actionId／內容，另建 attemptId。這可防失敗後無限改寫免費重送；不是對真實 API 計費的承諾。
3. 原行動失敗可使用本場一次技術重試；修改文字或對象屬新行動，需明示且佔新額度。重試已成功行動直接返回既有結果。
4. 最後一次行動失敗仍可用剩餘技術重試，不被玩家額度檢查誤擋；沒有重試額度時以已展示內容收尾。
5. 角色沉默是有效行為；服務錯誤、拒絕與額度耗盡分開，不能把技術問題演成真人沉默。旁聽只展示同一段剩餘事件，不自動開新生成請求。
6. 開始新行動、介入、暫停、離頁、結束或換場時增加 epoch，清除計時器並作廢舊 queued；回應必須同時符合 sessionId、actionId、attemptId、epoch 及未結束狀態才可接受。
7. 刷新後不自動重試或產生成本；未完成嘗試標示中斷，可人工重試。舊 queued 作廢，不把未看見的文字補入回顧。
8. 模擬額度與真實費用不同；取消畫面不能宣稱撤銷既有 API 成本。正式服務仍需後端硬限制、owner 驗權與去重，本輪前端不構成安全邊界。

## 7. 保存、清除、示例與舊資料

- 提升 schemaVersion，提供可重入遷移；先驗證／保存成功再移除舊資料，不用 `localStorage.clear()` 清整個網站。
- 新資料建議集中單一原型狀態 envelope，至少確保結束 A／保存歷史／啟動 B 不會部分成功。寫入失敗顯示「尚未保存，請保留此頁並重試」。
- 舊歷史沒有快照時標「舊版紀錄，缺少當時人物／來源版本」，可唯讀看既有已展示文字，不假造快照；再練需重新確認。
- 舊活動場缺乏可信快照時停止自動接續生成，提供保留回顧或重新建立；不能用最新人物資料悄悄補成舊場真相。
- 清除原型先列範圍：主原型、草稿、活動場、劇場歷史與舊引擎資料；確認前均不刪。取消保持所有命名空間內容一致。
- 清除只處理本原型的明確 key 清單，停止全部計時器／晚回應；不得碰正式 App 的 session、IndexedDB 素材或其他網站資料。
- 載入示例預設不覆寫已有資料：檢查主原型與劇場，顯示將取代的範圍；有資料時取消不變，確認後才載入一致的示例（建議預設）。不得只重置主原型留下孤立劇場。
- 舊引擎停止新增入口，既有歷史唯讀；不自動刪除、不零散移動封存原型。新舊資料若無法安全遷移，保留並回報阻礙。
- 多分頁建議以 revision 偵測舊頁寫入：衝突時停止寫入並提示重新讀取，保留可複製的文字；不宣稱 localStorage 可提供完整跨分頁交易。正式併發控制另案處理。
