```text
任務：LW-DB-001，Life World 的資料核對與 PostgreSQL 遷移驗收設計。
使用繁體中文，先讀 docs/team/BASELINE.md、docs/PRODUCT_GUIDE.md、
適用 AGENTS.md、app/db.py、app/migrations/、領域服務與現有測試。

工作範圍：只讀盤點與測試設計。獨立 work/lw-db-001 分支，
新增報告放 collaboration/data-audit/，該目錄目前尚未建立。
不要連正式資料庫、索取真實客戶資料、執行既有資料的 schema 變更、
重設帳號／積分、上傳資料或直接替換 app/db.py。
需要 fixture 時使用隔離虛構資料，記錄來源與清除方式。

交付一：現況盤點
- 找出每張表、主外鍵、唯一約束、owner 權限、版本與請求去重規則。
- 分清草稿與正式經歷、參與與提及、身分配對與私人關係、
  互動事件與多筆經歷、人物來源與衝突、私人筆記與正式成果。
- 列出 SQLite 專屬行為：PRAGMA、BEGIN IMMEDIATE、參數占位符、
  INSERT OR IGNORE、rowid、布林、JSON／文字、時間與圖片 BLOB。

交付二：PostgreSQL 映射與不變條件
- 保留 owner／ID／密碼雜湊／原文／時間／來源／精確小數與積分帳本。
- 資料型別、鎖與交易、唯一約束、排序與索引提出建議，標明未決項。
- 名片、影像與音訊只存私人安全參照；既有 BLOB 搬移要核對內容雜湊、
  MIME、歸屬與失敗恢復，不改寫來源為臆測事實。
- 密碼與帳號仍沿用既有成熟雜湊機制；不發明驗證協定。

交付三：可驗收案例與遷移流程
- 測試正常、空白、跨帳號、舊資料、時區、小數、重送、併發確認、
  revision 衝突、交易中途失敗及匯入重跑。
- 核對一次確認只有一份經歷／貢獻／任務／獎勵，同場多附件不重算見面。
- 提出來源只讀→備份→dry-run→隔離匯入→比對→切換→回復演練；
  列出切換後新增資料如何保存，不假設直接還原舊檔就能安全回退。
- 比對列數、ID、關聯、帳本總量／逐筆、標準化時間與精確數值；
  格式差異與實質資料差異分開，不能只比較文字化 DB dump。
- PG 測試必須在真實隔離 PostgreSQL 執行；SQLite 綠燈不能替代。

可選的只讀驗證工具須先列需求與邊界、先用 pytest 跑有效紅燈，
再實作、跑綠燈及必要回歸；所有新自有程式／測試逐行補中文註解。
無 PG 或執行環境時交測試設計與限制，不宣稱遷移／併發已通過。

最後依 docs/team/HANDOFF_TEMPLATE.md 交付資料關聯圖、映射表、
測試矩陣、差異報告、風險與待審契約。由全端審查後才另立匯入實作任務。
```
