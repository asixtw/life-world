# HabitScheduleDisclosure v0.3｜本機實作與驗收

日期：2026-11-03。依 Boyi 本輪核准計畫，實作正式 App 與 Prototype 的唯讀月曆。[原始審查草案](team/goal-detail/HABIT_SCHEDULE_v0.3.md)保留原貌；本頁記錄本輪採用範圍及實際證據。

## 本輪行為

- 取代習慣卡及後段排程中的長日期字串，不動既有排程編輯器。每張卡預設收合，展開後逐月查閱，週一為首欄，最多31個日期按鈕與月首補位。
- 進行中／待回顧目標優先今天所在月，夾於有效邊界；完成／結束目標優先最後有安排月份，無則起始月。舊資料沒有明確日期或期間時，不使用舊星期規律推算展示。
- 月份請求明確指定 `start=max(月首,目標起日)`、`end=min(月尾,截止日)`。既有 `GET /api/goals/{id}/calendar` 回傳 `date / action_ids / planned_quantities`，用量由後端處理版本；無新API、無migration。
- 已安排、未安排、今天、已選日期以文字／符號與框線區分；期間外禁選。已選有安排日顯示該日預期量，未安排日顯示沒有安排。實際投入始終標示「暫無逐日統計」，不從累積或七日筆數推算。
- 未來日只讀；今天／過去日且後端允許record時，可進記錄。帶入目標／習慣及日期，時間欄必須由使用者填寫，依目標固定時區轉UTC；不預填實際貢獻量。未明確保存不建立經歷或草稿。原型若已有非空草稿，不直接覆蓋。
- 320px使用接近滿寬的內嵌月曆、零欄間距，日期按鈕至少44px；月份工具列可換行。沒有新Dialog或點陣美術。

## 狀態與隔離

月份、選日、展開與捲動保存在前端記憶體，同次登入返回可恢復，刷新回預設。切月／選日不改URL、不新增History entry；沒有實作全站Router或瀏覽器Back補償。

快取包含owner、goal、action與目標版本；版本改變使用新的檢視狀態，登出或失去權限清除。切頁使待處理月份回應失效。失敗保留上一個成功月份與選日，明示錯誤並重試，不把錯誤當成空月。正式App取得權限錯誤不繼續顯示該月私人資料。

共用 `schedule-model.js`／`schedule-view.js` 在正式App為來源，Prototype保存逐位元組相同副本；pytest核對一致性。正式adapter透過既有API取得資料，原型adapter只讀本機虛構排程；原型版本簽章留在UI記憶體，不放整串日期到DOM快取鍵。

導覽草案仍由工作區既有設計／研究參考入口查閱，本輪不修改原始交接包，也不把草案宣稱為已核准的Router契約。

## TDD及驗收

- 新增日期模型與共用來源檢查，功能缺失時5項紅燈；實作後5項綠燈。
- 指定Node執行完整pytest：`LIFEWORLD_NODE=/可用Node路徑 .venv/bin/python -m pytest -q`。本輪189 passed，0 failed／0 skipped（10.44秒）。沒有Node時前端模型案例會明確skip，不冒充已驗證。
- 初步7項瀏覽器驗證通過：手機／桌面、查閱無資料寫入、返回／刷新、未來日期、失敗重試、用量版本、首尾月與晚到回應。加入目標時區補記及必填時間驗證後，完整瀏覽器回歸 **143 passed，0 failed／0 skipped（201.32秒）**。另補369日排程連切六個月的DOM／History／資料不變案例：1 passed、8 deselected（1.56秒）。最後改善切月焦點保留，完整月曆專用案例重驗 **9 passed（7.99秒）**；不將補測數與完整回歸數重複相加。
- 所有瀏覽器測試使用隔離虛構資料服務，截圖轉存測試目錄，避免改寫既有驗收圖片。

未執行實機Safari／Android、完整螢幕閱讀器驗收；一般Chromium結果不能代替實機手勢或錄音驗證。沒有修改資料庫結構、既有採計／獎勵交易、人物或劇場資料；沒有Commit、Push、Merge或部署。
