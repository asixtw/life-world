## 新的主流程

歡迎 → 訪客開始／登入 → Bio → 第一個目標及行動設定 → 確認建立第一顆目標蛋 → Lumi 誕生 → 世界。

日常：記錄事件 → 人物選填 → 若選擇新增／關聯人物且尚為訪客，先升級帳號並返回 → 填寫本次行動貢獻 → AI 整理（可選）／手動整理 → 使用者確認 → 保存、累計及積分。

補記：選實際發生日期／時間 → 填事件與本次貢獻 → 人物選填及帳號門檻 → 使用者確認 → 補記保存與積分 → 回讀紀錄。

成果完成：目標詳情 → 我已達成成果 → 拍攝／上傳相關佐證 → 檢視上傳結果 → 使用者手動確認 → 完成狀態與成果回顧。具體佐證門檻待細化。

## 實作保障，不改變使用者裁定權

使用者決定內容與累計，後端負責保存、所有權驗證、交易一致性與同一提交的重試去重。這兩件事不互相取代。補記無須因晚記而被拒絕，但具體積分與歷史狀態影響不能在規則未定時自行發明。

## 下一批原型修訂

1. 首次引導強制目標，將 Lumi 見面移到第一顆目標蛋建立後。
2. 訪客進入、升級與返回原事件的流程；人物新增／關聯操作攔截。
3. 經歷人物選填、本次貢獻確認及補記發生日期。
4. 成果拍攝／上傳、手動確認完成；取代行動次數達標即完成的簡化設計。
5. 活力先保持中性呈現，不增加負向衰減。
