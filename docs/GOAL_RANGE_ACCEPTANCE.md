# 正式 App｜目標期間貢獻採計修正與驗收

更新：2026-11-02。Boyi 確認先修正式 App 日期邊界，再整包合併 PR #4。本輪不部署、不操作使用者實際 DB，也不納入另案 GCP Step 07 設定。

## 規則與實作

- 進行中目標只採計目標期間內的經歷：`start_date ≤ 發生日期 ≤ deadline`；以建立目標時固定的 `schedule_timezone` 轉換，不用客戶端或後來修改的帳號時區。
- 期外且帶貢獻的確認回 422／`contribution_out_of_range`，提示移除貢獻。整筆確認在原交易內回滾，不留下經歷、任務、人物更新、進度或獎勵，原草稿保留。
- 使用者移除貢獻後可保存原經歷，照既有經歷規則獲得一次開發用獎勵；同請求重試不重複保存或發獎。不自動刪除或偷偷忽略使用者填寫的貢獻。
- 待回顧與待補設定目標仍將貢獻存為 pending，不能直接累計。延長後沿用逐筆日期核對；歷史目標仍拒絕新增正式貢獻。
- 若進行中目標缺期間／時區，回 409／`goal_setup_required`，不猜測邊界。沒有貢獻的補記不受採計期間限制。
- 修改點限 `GoalsMixin._save_goal_contributions()`，不改 SQL 結構、migration、既有歷史資料或獎勵規則。確認的權限、版本與重送去重仍由原流程處理。

## TDD 與測試前置資料

新增 `tests/test_goal_contribution_range.py` 九項案例：台北／洛杉磯／UTC 開始前一秒、首日零點與截止日最後一秒、帳號時區改變、到期 pending、舊資料期間未知，以及失敗原子性、移除採計與重送。

先在原程式執行：**4 failed、5 passed，0.51 秒**，明確重現期外被接受；修正後同九項 **9 passed，0.48 秒**。

第一次後端回歸有 27 項失敗，查明共用成功 fixture 的發生時間原本是目標建立前一天。依已確認規則將該 fixture 改為台北開始日 00:10，保留各測試原有權限／回滾／精確進度／獎勵／重送斷言；UTC 精確時間斷言同步改為前日 16:10，仍驗證正確時區轉換。很久以前的經歷案例改為不帶新目標貢獻，保留「可補記且正常獲得經歷獎勵」斷言，另加零目標進度斷言；拒絕舊日期灌入新目標的行為由新增專用測試覆蓋。不是刪除失敗案例或放寬採計限制。

修正後完整後端：`python -m pytest -q --tb=short` **185 passed，0 failed，0 skipped，9.98 秒**。原有 176 項與新增九項一併通過。

## 瀏覽器與發布驗收

正式 UI 新增案例：以很久以前的日期填寫貢獻，收到期外提示且摘要保留；清空採計量後保存同一份經歷，零目標進度且只獲一次原有獎勵。

既有帳號升級旅程保留 2001 日期與數量的升級還原斷言；在真正採計前由使用者改回本次目標期間內日期，不再要求期外日期增加進度。

首次完整瀏覽器回歸 **1 failed／145 passed，214.51 秒**：帳號升級旅程在保存人物的 modal 尚未關閉時改動背景日期，被未完成的表單還原覆寫。補上等待保存／還原完成，不加固定 sleep、不刪斷言；針對升級與期外保存兩項重跑 **2 passed、2 deselected，8.82 秒**。

最終完整瀏覽器回歸：`python -m pytest browser_tests -q --tb=short` **146 passed，0 failed，0 skipped，211.81 秒**。透過既有 screenshot 包裝只導向暫存目錄，不改測試斷言；使用隔離測試服務／DB 與 Chromium。真機 Safari／外部 AI／PG 實例不在本輪測試聲明內。
