# 後續整合與仍待決定的規則

這個 App 是能保存與操作的本機 MVP。以下保留為後續工作，不用假畫面或空函式宣稱已完成。

## 產品規則

1. 確認正式貢獻單位、部分完成粒度、歷史更正及撤銷規則；目前支援使用者輸入正數，最多六位小數。
2. 確認補記正式積分、歷史版本、未排程日、暫停／完成後日期的計算。現在活躍目標的過去紀錄可保存給分；已完成目標的新貢獻回 policy_required 並保留草稿，可移除貢獻只保存真實經歷。
3. 確認成果佐證種類、必填條件、格式、大小與失敗退路。開發模式至少一份有效 PNG／JPEG、最大 5 MiB，不代表正式裁定。
4. 決定 GE-04 的 B 或 C+；現在不做負向衰減，Progress／Growth 不因缺席減少。
5. 決定主動結束、恢復、完成後更正，避免擅自建立正式狀態轉換。
6. 同一真實事件的多草稿／附件辨識、人工合併／拆分、來源撤回；目前保證提交／草稿去重，不宣稱已解決語意去重。

## 正式系統

- 先取得正式程式庫與核准技術契約，決定本機實作如何合併；不要直接覆寫團隊來源。
- 將本機帳號 adapter 換為受管 OIDC／OAuth 身份，處理驗證、找回、session 政策、登入限制與多裝置退出。
- 若正式基準仍為 PostgreSQL，依本機已驗證的狀態與不變條件移植 repository／migration，驗證併發交易，不能只換連線字串。
- 使用受權限保護的雲端物件儲存、上傳限制／掃描／重試、保留期限及刪除策略。現有 BLOB 方案適合本機驗證。
- 接入真實 AI provider、設定與金鑰管理、輸出 schema／來源、錯誤與成本測試；維持候選與人工確認的界線。
- 排程例外與歷史版本、人物 360° 維度／事實證據、完整小劇場、夜間關懷與 Quiet UI、動效及 Figma 對齊分批加入。
- 正式備份／還原演練、CI、容器或部署設定、監控與操作文件需依團隊環境落實；未建立指向未知服務的假部署設定。

## 每次接續作業

先補需求與正常／異常／邊界測試，執行紅燈；再修改實作、重跑測試，將真實結果與限制記入 `ACCEPTANCE.md`。不改寫來源 U-01～06 來配合較容易的程式。
